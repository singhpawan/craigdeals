## Problem Statement: Automated Tag Propagation from Databricks to Snowflake
Problem:
There is a critical metadata gap between our Databricks lakehouse and Snowflake data warehouse. Business, operational, and sensitivity tags applied to data objects in Databricks Unity Catalog are not being propagated to their corresponding objects in Snowflake. This absence of synchronized metadata undermines our ability to enforce consistent data governance, manage security risks, and enable effective data discovery in our primary analytics environment. The current state creates an unscalable operational burden and prevents the uniform application of data policies across platforms.

Objective:
To design and implement a fully automated and scalable framework that ensures the reliable, timely, and accurate propagation of all metadata tags from Databricks to Snowflake.

Key Requirements:

Automation: The solution must be a zero-touch process, automatically handling the synchronization of tags for new, updated, or deleted tables, columns, and tags without any manual intervention.

Scalability: The framework must perform efficiently and cost-effectively as the volume of data assets scales to thousands of tables and millions of tags.

Timeliness: Tag changes in Databricks must be reflected in Snowflake within a defined, low-latency Service Level Agreement (SLA), targeting near real-time updates.

Reliability: The system must be resilient, incorporating robust error handling, retry mechanisms, and proactive alerting to ensure data governance consistency is never compromised.

2. Executive Summary

Our organization has successfully established a data flow from our Databricks lakehouse to the Snowflake data warehouse. However, we face a critical metadata disconnect: the business, operational, and sensitivity tags meticulously applied in Databricks Unity Catalog are lost when data lands in Snowflake. This gap breaks our data governance framework, exposes the company to significant compliance risk, and cripples data discovery. We propose the development of an automated, scalable, and resilient Tag Propagation Framework to ensure metadata consistency across our core data platforms, transforming them into a single, trustworthy data ecosystem.

4. Problem Statement

The current inability to propagate metadata tags from Databricks to Snowflake creates a fragmented and untrustworthy data environment with severe business consequences:

Critical Governance Gap: We operate with two conflicting sources of truth for metadata. This prevents the enforcement of consistent security policies (e.g., row-level security, column masking), leading to a high risk of data misuse and unauthorized access in our primary analytics platform.

Operational Inefficiency and Toil: Data engineering and governance teams are forced into error-prone, manual processes to replicate tags. This is not scalable and introduces significant delays in making data available for business use, directly impacting time-to-insight.

Impeded Data Democratization: Our goal of enabling self-service analytics is undermined. Without reliable business and quality tags in Snowflake, data consumers cannot effectively discover, understand, or trust the data, leading to a reliance on overburdened central teams and a proliferation of data silos.

Unscalable Architecture: As we scale our data ingestion from dozens to hundreds of sources, the manual metadata reconciliation workload will grow exponentially. This technical debt represents a fundamental blocker to the future growth and maturity of our enterprise data platform.

5. Goals & Success Metrics

The goal is to deliver a fully automated framework that guarantees tag consistency between Databricks and Snowflake.

Success Metrics:

Metadata Accuracy: Achieve >99.9% parity between Databricks UC tags and Snowflake tags within 1 hour of a change.

Reduction in Manual Effort: Reduce manual ticketing and effort related to tag management by 100%.

Time-to-Propagation: All metadata changes (new tags, updates, deletions) must be reflected in Snowflake within a 15-minute SLA.

Scalability: The system must handle a 10x growth in tables (from 1,000 to 10,000) over the next 18 months without requiring architectural redesign.

6. Key Requirements & Acceptance Criteria

To be considered successful, the solution must meet the following criteria for automation and scale:

Automation Requirements:

A1: Zero-Touch Propagation: The end-to-end process of detecting a change in Databricks and applying it in Snowflake must be fully automated with no human intervention.

A2: Dynamic Object Handling: The system must automatically detect and propagate tags for newly created tables, views, and columns without requiring manual registration or configuration.

A3: Full Lifecycle Sync: The framework must handle the creation, update, and deletion of tags and tag associations seamlessly.

A4: Intelligent Error Handling: The solution must include automated retry logic for transient failures and send proactive alerts (e.g., via Slack/PagerDuty) to the platform team upon persistent synchronization failures.

Scalability & Performance Requirements:

S1: High-Throughput Design: The system must be architected to process metadata for thousands of objects efficiently, avoiding full-catalog scans in favor of incremental or event-driven processing.

S2: Low Latency: The P95 latency for reflecting a single tag change in Snowflake must not exceed the 15-minute SLA.

S3: Resource Efficiency: The solution must operate with minimal computational overhead on both the Databricks and Snowflake platforms to manage costs effectively.

S4: Extensibility: The core framework should be designed with extensibility in mind, allowing for the future addition of other metadata sources or destinations (e.g., Collibra, Power BI) with minimal rework.

7. Out of Scope for V1

Synchronization of other metadata types, such as table comments or user-defined properties, unless they are implemented via the tag system.

A user interface for managing synchronization rules. All configuration will be managed as code.

## Approach 1: Event-Driven Propagation with Serverless Functions
This approach uses cloud-native services to react to changes in Databricks in near real-time and apply them to Snowflake immediately.

How it Works:

Capture Events: Databricks Unity Catalog audit logs are configured to stream to a cloud storage location like AWS S3 or Azure Blob Storage. These logs contain detailed records of every metadata change, such as setTag on a specific table.

Trigger Action: A serverless function (e.g., AWS Lambda or Azure Function) is automatically triggered whenever a new log file arrives.

Apply Tags: The function parses the log to identify the table/column, the tag, and its value. It then connects to Snowflake and executes the necessary SQL commands (CREATE TAG IF NOT EXISTS, ALTER TABLE ... SET TAG) to apply the identical tag to the corresponding object.
