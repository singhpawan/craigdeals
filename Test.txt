Problem Statement

The Voltage DPaaS root certificate authority has reached end-of-life and will no longer issue new certificates. Our current DPaaS certificates expire on February 27, 2026—less than three weeks away. The WP Crypto/Security team has already deployed the updated certificate to the Dev environment (January 28), which has broken all our dev Snowflake environments. The Worldpay platform team is planning to upgrade the certificate in production on February 17, before the certificates expire on February 27. We must deploy the updated Lambda module with the new certificates issued by the WP Cyber/Security team on or before February 17.

Business Risk: If we do not deploy the updated certificate by February 17, all DPaaS-integrated workloads will fail simultaneously in production Snowflake accounts. The recovery timeline would be unpredictable, as we would need to request emergency certificate issuance and coordinate deployment across multiple environments under pressure.

Impact and Severity: This is a hard dependency for all data products consuming DPaaS services. The impact spans ingestion pipelines, transformation workloads, reporting systems, and any downstream analytics that depend on Voltage for data connectivity. We've already observed query failures in Dev, confirming that the old certificate is no longer accepted by the DPaaS Lambda. All production workloads on Snowflake will be affected on February 17 unless we complete the upgrade beforehand.


Upcoming Change

The WP Crypto/Security team is scheduled to formally upgrade and provide the new certificate on February 17, 2026.


Current State

Deployment and Infrastructure Gaps: The legacy Lambda function responsible for DPaaS connectivity was never migrated from the WP private repositories to the FIS GitHub account, leaving us without a proper build and deployment pipeline. There is no active Jenkins pipeline for building or deploying this Lambda, and our team's access is currently limited to the Dev AWS account only. The WP team retains access to the Prod AWS account. I have obtained access to the legacy code repositories and migrated the Lambda code to the FIS EDAI GitHub account.

Proof of Concept and Validation: We attempted a local build in the standard development environment, but the process failed due to VPN certificate retrieval being blocked by Global Protect. However, one WP engineer (Sumanth) with an older development machine was able to successfully build the deployment package. This package was manually deployed to a single Dev WP EU Snowflake account, and we've confirmed that the new certificate functions correctly. This validates the overall approach but also exposes our current operational fragility. To avoid or minimize downtime, we will need to collaborate closely with the WP Crypto/Security team.

Certificate and KeyStore Configuration: The current implementation loads certificates into the Java KeyStore as a single entry. The existing architecture does not leverage the KeyStore's native capability to maintain multiple certificate aliases simultaneously. This limitation might force us into an all-or-nothing cutover rather than a gradual, zero-downtime rotation strategy. Our research indicates that JKS (Java Key Store) can store multiple certificates. The WP platform team has chosen to replace the certificate rather than maintain both old and new simultaneously. We can work with them to explore supporting both old and new certificates during the migration on February 17.


Plan of Action

Phase 3: Production Deployment (February 16–17)
* Coordinate with the WP team to deploy the dual-certificate Lambda to Worldpay US Prod and Ethos US Prod in a staggered fashion. This reduces the blast radius of any unforeseen issues and allows observation of the upgrade in lower-risk environments before completing the final rollout.
* Monitor certificate validation logs and client connection patterns in Prod for 24 hours post-deployment to confirm stable operation.
* Once we have confirmed stable dual-certificate operation for two weeks and the February 27 expiration date has passed, schedule a cleanup deployment that removes the old certificate alias from the KeyStore.
